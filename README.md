# e护校园 · 反诈研判 Streamlit 预览版

> 校园金融反诈 AI 助手。**只分析用户主动输入的文本**，不监听通话、不录音、不申请任何系统权限。
> 与已上线的《e护校园 · 小程序原型预览》保持同一套演示口径。

---

## 1. 文件说明

| 文件 | 作用 |
| --- | --- |
| `app.py` | Streamlit 界面：输入、研判、结果卡片、科普、导出 |
| `anti_fraud_engine.py` | **端侧规则研判引擎**（纯标准库、零依赖），可被小程序/云函数/后端直接复用 |
| `requirements.txt` | 依赖清单 |

核心设计：**端侧引擎与大模型输出同一套结构化字段**，前端可无感切换；
大模型（DeepSeek）用于"解释为什么可疑"，端侧引擎负责"没网没 Key 也不翻车"。

## 2. 原始版本存在的问题（本版已修复）

| # | 问题 | 影响 |
| --- | --- | --- |
| 1 | 代码里混入了 `\` 续行符和大量空行 | 直接 `SyntaxError`，**根本跑不起来** |
| 2 | 没有 API Key 就完全无法演示 | 评委面前断网/没额度 = 演示失败 |
| 3 | 大模型一旦超时或返回非 JSON 就整页报错 | 报错截图比没演示更糟 |
| 4 | `deepseek-reasoner` 不支持 `response_format=json_object` | 选这个模型必崩 |
| 5 | 模型返回字段缺失/类型不对时直接 `KeyError` | 结果页白屏 |
| 6 | 提示词硬编码在界面里，无法迭代 | 改一次要动主文件 |
| 7 | 无输入长度限制、无历史记录、无导出 | 演示与复盘的体验都差 |

## 3. 本地运行

```bash
pip install -r requirements.txt
streamlit run app.py
```

浏览器打开 `http://localhost:8501`。

### 两种研判模式

- **端侧规则引擎（离线兜底）** —— 默认。11 类高危信号 + 10 类校园高发骗局，
  全程在本机完成，**不需要 Key、不需要联网**。适合现场演示保底。
- **大模型研判（DeepSeek）** —— 展示真实 LLM 结构化研判能力。
  Key 有三种注入方式，推荐后两种，避免 Key 出现在演示画面上：
  1. 左侧侧边栏直接填写；
  2. 环境变量 `DEEPSEEK_API_KEY`；
  3. `.streamlit/secrets.toml`：

     ```toml
     DEEPSEEK_API_KEY = "sk-xxxx"
     ```

  > 大模型调用失败（断网、额度、解析异常）时会**自动降级**到端侧引擎并给出提示，演示不中断。

## 4. 端侧引擎的评分口径（评委问起来可以这么答）

```
score = 100 × (raw/100)^0.7
raw   = 0.9 × 风险动作信号分 + 0.45 × 话术类型匹配分 − 可信上下文抑制分
```

1. **风险动作优先**：文本里"正在被引导做什么"最重——要求转账/垫付、索要验证码、
   要求屏幕共享、下载陌生 APP、资金清查等，每项带独立权重。
2. **话术类型次之**：再判断"像哪一类骗局"（快递理赔、刷单返利、冒充老师/公检法、
   校园贷注销、游戏交易、门票、兼职、助学金、杀猪盘）。
3. **抑制误报**：出现"由学院统一审核""学校不会通过电话索要银行卡"这类正规流程表述时，
   自动扣分并降档 —— 否则正规的助学金通知会被误判。
4. 0.7 次幂做一次拉伸：多个信号叠加的文本迅速逼近高危，只含弱关键词的文本仍停留在安全/低危。

### 自测（内置 12 个场景，含 3 个正常文本对照）

```bash
python anti_fraud_engine.py
```

当前标定结果：

| 场景 | 等级 | 分值 |
| --- | --- | --- |
| 快递理赔 + 屏幕共享 + 索要验证码 | 高危 | 98 |
| 冒充公检法 + 安全账户 | 高危 | 89 |
| 冒充老师 + 急事借钱 + 要求保密 | 中危 | 59 |
| 校园贷注销 / 影响征信 | 中危 | 59 |
| 刷单返利 | 中危 | 47 |
| 演唱会门票代抢 | 中危 | 47 |
| 游戏账号解冻费 | 低危 | 28 |
| 正规助学金通知（对照） | 安全 | 0 |
| 正常快递取件短信（对照） | 安全 | 10 |

> 规则阈值集中在 `anti_fraud_engine.py` 顶部（`SCAM_RULES` / `SIGNAL_RULES` / `SAFE_CONTEXT_RULES`），
> 可按学校实际案例继续加词，不必改动界面。

## 5. 部署到 workbuddy / 云主机

`app.py` 是标准 Streamlit 入口，任意支持 Streamlit 的平台都可直接用：

- **入口文件**：`app.py`
- **启动命令**：`streamlit run app.py --server.port $PORT --server.address 0.0.0.0`
- **Python 版本**：3.9+
- **环境变量**：`DEEPSEEK_API_KEY`（可选）

重新部署后记得确认首页指向的是这一版，而不是旧的静态预览页。

## 6. 演示脚本（90 秒）

1. 讲一句定位：「我们只分析**你主动粘贴**的内容，不监听、不录音。」
2. 点侧边栏 **📦 快递理赔** → 点「开始研判」→ 高危 98 分，命中"索要验证码 / 屏幕共享 / 陌生 APP"。
3. 展开 **🔍 每个信号为什么危险** → 讲设计亮点：不是黑盒打分，每个结论都能解释、能落到反诈教育。
4. 点 **✅ 正常文本（对照）** → 安全 0 分 → 说明误报抑制：正规助学金通知不会被误伤。
5. 切到 **大模型研判** 再跑一次同一条话术 → 说明同一套输出协议，规则与大模型可替换、可互相校验。
6. 收尾：导出 JSON → 这份结构体就是小程序端要展示的内容。

## 7. 口径红线（务必遵守）

- 不声称能 **实时监听通话 / 录音** —— 微信小程序无法在通话中运行，平台不允许，合规也不允许。
- 不索要、不复述用户的**身份证号、银行卡号、验证码**。
- 结论一律用"疑似""高危特征""建议"，不下绝对判决。
- 演示话术是**脚本化**的，回答"通话内容哪来的"时如实说明。
- 本预览仅用于比赛演示，不构成法律意见。
